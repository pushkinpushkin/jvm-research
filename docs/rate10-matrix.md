# Часовая серия 10 RPS на VPS

Методика и критерии допуска: [RESEARCH_PROTOCOL.md](../RESEARCH_PROTOCOL.md).
Серия исследует дополнительную нагрузку; автоматическая валидация сама по себе
не доказывает стабильность памяти и не делает результат эталонным.

## Запуск

Нужны подготовленный выделенный Linux VPS, Docker, k6, Python 3, Git, tmux,
чистые исходники и свободные порты стенда. Скрипт не устанавливает инструменты
и не обновляет Git. Сначала завершите текущий эксперимент.

```bash
cd ~/jvm-research
bash scripts/run-vps-rate10-matrix.sh --dry-run
tmux new -s jvm-rate10-matrix
bash scripts/run-vps-rate10-matrix.sh 20261006-rate10-1h-v1
```

Второй аргумент необязателен: путь к репозиторию по умолчанию определяется
относительно скрипта. SERIES_ID выбирается один раз и сохраняется при продолжении.

Скрипт предварительно загружает образы и собирает все четыре runtime, включая
Native. Затем выполняет 12 последовательных запусков: 1 час при 10 RPS,
drain до 300 секунд, 1 час post-idle. Порядок показан в dry-run.
Время измерений — минимум 24 часа, дополнительно нужны сборки и подготовка.
Каждый runner создаёт собственный стенд и удаляет его после сохранения результатов.

Не запускайте другие стенды или сборки и не обновляйте исходники/образы во время
серии. Скрипт проверяет изменения перед очередным запуском; он не может запретить
внешнему процессу менять окружение во время измерения.

## Наблюдение и продолжение

```bash
tail -f results/vps-rate10-1h/20261006-rate10-1h-v1/matrix.log
run_dir=$(cat results/vps-rate10-1h/20261006-rate10-1h-v1/current-run.txt)
cat "$run_dir/phase.txt"
```

Для отсоединения от tmux: Ctrl+B, затем D. Для возвращения:
`tmux attach -t jvm-rate10-matrix`.

Повторите исходную команду, чтобы пропустить завершённые запуски с сохранённым
кодом 0 и `eligible: true`. Частично завершённый запуск не продолжается с середины.
После изучения причины ошибки можно сохранить старую попытку в `_attempts`
и повторить этот запуск:

```bash
bash scripts/run-vps-rate10-matrix.sh \
  20261006-rate10-1h-v1 "$PWD" --retry-failed
```

Ошибка runner или отказ валидатора останавливает всю серию. Результат за пределами
SLO нужно учитывать как ограничение runtime, а не перезапускать до случайного успеха.
При изменениях кода, инструментов или образов используйте новую серию; не удаляйте
контрольные файлы, чтобы обходить проверку совместимости.

Одиночные прогоны и серии внешнего скрипта автоматически не импортируются.
Работающую серию прежнего скрипта следует завершать той же версией: смена wrapper
меняет его контрольную сумму.

## Проверка без Docker

```bash
bash -n scripts/run-vps-rate10-matrix.sh
python3 -m unittest discover -s scripts/tests -p 'test_rate10_matrix.py' -v
```

Тесты подменяют Docker/k6 и проверяют порядок, остановку, архивирование неудачной
попытки, продолжение и отказ при смене образов. Они не измеряют реальные JVM.
