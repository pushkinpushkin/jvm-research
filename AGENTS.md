# Работа над JVM-исследованием

Сначала прочитай `RESEARCH_PROTOCOL.md` и `CURRENT_STATE.md`. Читай `DECISIONS.md` и `RESULTS_SCHEMA.md` только в части, нужной для текущей задачи; `BACKLOG.md` — для выбора следующего этапа.

Постоянный контекст: протокол, существенные решения, схема результатов. Временный контекст: актуальный checkpoint и оставшийся backlog. Сырые результаты и логи хранятся в `results/` или артефактах CI, а не в этих документах. Не дублируй правила в README и runbook: используй ссылки на канонический файл.

Один этап — один законченный инженерный вопрос: наблюдение → гипотезы → адресная проверка → изменение при необходимости → проверка → вывод. Выполняй уже согласованный объём работы; это правило не повод бросать начатую задачу или запрашивать повторное разрешение.

Порядок чтения: protocol/state → компактный summary → конкретный source file → нужный фрагмент лога → сырые данные. Полный повторный аудит нужен только при изменении релевантного кода, хоста, образа, cgroup, сборщика, парсера или методики, либо при обнаруженной зависимости. Сначала установи факт, затем объясняй причину; перед глубоким исследованием запиши проверяемые альтернативные гипотезы.

Не выводи полные CI-логи, raw JSON или все samples в контекст. Для `phase-summary.json` сначала извлекай `phases`, не `runtimeSamples`; сначала читай `validation.json` и поля manifest из `metadata.json`. Raw открывай для аномалии, временного ряда или независимого пересчёта.

Закрывая этап, обнови `CURRENT_STATE.md`: цель, проверенный результат с commit/run ID, изменения, ограничения, следующий неизвестный вопрос. Замени устаревшее состояние, не дописывай бесконечный дневник. Добавляй в `DECISIONS.md` только решения, влияющие на будущие этапы; из `BACKLOG.md` удаляй завершённое. Не называй реализацию доказательством, smoke — baseline, working set — RSS, отсутствие метрики — нулём.

Не переходи к полной матрице до корректного HotSpot baseline. Идеи глубокого GC/JIT/assembly-анализа сохраняй в backlog, пока наблюдение не требует их проверки. Этап завершён, когда цель достигнута и checkpoint позволяет продолжить без истории переписки. Итоговый ответ короткий: результат, доказательства, ограничения, следующий шаг.
